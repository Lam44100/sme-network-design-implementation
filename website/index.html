    02 / Understand the design

    A small network with clear responsibilities

    Download full design ↗

    Switch locally. Route between VLANs.

    Access ports place PCs in VLANs. Trunks carry VLAN-tagged traffic. R1 uses one subinterface per routed VLAN to provide its default gateway—known as router-on-a-stick.

    R1 sends external traffic to R2 through a default route. R2's four return routes point back to R1 so replies can reach the originating subnet.

    Two physical links, one logical trunk.

    LACP combines SW1 and SW2's F0/23 and F0/24 ports into Port-channel 1. STP sees the bundle as one logical link. Multiple flows may use different members; a single flow does not get the sum of both links' bandwidth.

    SW1 is configured as the PVST root primary for VLANs 10, 20, 30, and 99. The bundle adds member-link redundancy, not router or switch redundancy.

    How a PC gets an address
    1. Discover: a PC in DHCP mode broadcasts on its access VLAN.
    2. Offer: R1 offers an address from that VLAN's pool.
    3. Request: the PC requests the offered lease.
    4. Acknowledge: R1 confirms the lease, including mask and gateway.

    R1 is directly attached to the VLANs, so no DHCP relay is needed. Exclusions reserve .1–.20 for the user VLANs and .1–.30 for management. Actual leases can vary.

    The original DNS option is 8.8.8.8, but the lab does not demonstrate a working path to it. Use IP addresses for the documented connectivity tests.

    Trunks allow 10, 20, 30, 99, and 999; native VLAN is 999. Unused switch ports are assigned to VLAN 999 and shut down.

    Security controls and their boundaries

    The scripts configure SSHv2 on VTY 0–4, local login, port security with one sticky MAC and restrict mode, PortFast and BPDU Guard on access ports, and disabled DTP. Channel members explicitly disable edge-port protections.

    No inter-VLAN ACL is configured. Guests can reach management in the baseline. Management VLAN addressing separates broadcast traffic; it is not an access policy.

    Classroom credentials and 1024-bit RSA keys are retained. These are educational examples, not a production-hardening baseline. Configuration presence does not prove a security event was tested.

    04 / Open it yourself

    From the page to Packet Tracer

    1. Download the lab. Open enterprise-network.pkt in Cisco Packet Tracer and work on a copy.
    2. Use Realtime mode. Let links settle. The file opened in 9.0.0.0810 during packaging; this does not establish full functional compatibility.
    3. Start with PC-GUEST. Desktop → Command Prompt shows addressing and the route toward the external server. Running these commands is optional.

    If the first ping loses a packet, allow ARP resolution and repeat. Record actual results; don't infer success from this model. Traceroute shows routers, not Layer 2 switches.

    PC-GUEST · optional commands
    ipconfig

    Rebuild, credentials, and troubleshooting

    Use two Cisco 2911 routers, two 2960-24TT switches, four PC-PT devices and one Server-PT. Cable the port map above, then apply SW1, SW2, R1 and R2 scripts to fresh devices. Respond to interactive prompts before continuing. Set internal PCs to DHCP and the external server to 198.51.100.10/24 with gateway 198.51.100.1.

    The scripts define console cisco, enable class, and SSH admin / admin. These are public lab-only examples. One limited R1 console attempt did not authenticate during packaging; its cause is unresolved. Saved lab access settings have not been reconciled with the scripts. Do not overwrite the original if your copy differs.

    For DHCP issues, inspect access VLANs, allowed trunk VLANs, subinterfaces, and pools. For external reachability, check the forward route, return routes, and server gateway. For LACP, compare mode and trunk settings on both members. The scripts' July 2026 clock setting is not a capture timestamp.

    Project context

    Built as a group lab. Presented as a portfolio case study.

    The topology, configurations, and original results come from the NET2201 Computer Networks group assignment. Credit for that baseline belongs to the original project group. This personal portfolio edition adds clearer documentation, recovered evidence, and this interactive explanation; it does not claim sole authorship of the original implementation.

    What the design teaches

    Consistency matters across VLAN IDs, trunk lists, DHCP pools, gateways, and return routes. The original report describes corrections to BPDU Guard scope and RSA command syntax; those are historical report statements, not newly reproduced faults.

    What it does not claim

    No real Internet access, physical deployment, production security, measured failover, or full high availability. Guest-to-management routing remains permitted. R1 and SW1 are single points of failure.
